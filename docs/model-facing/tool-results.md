## 拒绝和出错

主模型用 Edit、Write 改 `~/.refrain/` 下的文件：

```
~/.refrain/ 下是记忆的存储，由后台自动整理，不能直接修改。如果用户要改某条记忆，先用 read 把当前内容念给他核对，再告诉他"已记下，接下来后台整理时会按你的话更新（一般在几轮对话之内）"。如果用户只是让你记住某件事，不需要写任何文件，后台会从对话里整理。
```

主模型调用 submit：

```
submit 只供后台整理使用，和用户对话时不需要调用，包括用户让你记住或整理记忆的时候。
```

数据库暂时读不到：

```
这次检索没能完成：记忆库暂时读不到（数据库正被占用或出错）。可以先不依赖记忆继续工作，之后需要时再试。如果回答用户需要查以前的记录，就告诉他暂时查不到。
```

## submit（只有书记员会看到）

校验不通过：

```
有 3 处问题，这次提交没有保存。请改好后整份重新提交（还可以再交 2 次）：
1. knowledge（update K12 "先讨论再动手：给出推荐，等用户确认后再改文件；涉及个人配置的…"）：正文 455 字，超过上限 400 字，至少要删掉 55 字。一条知识只写结论；文档、来源这类清单只写去哪看，不逐个列；原话最多留一两句，优先留最新的，更早的出处会自动保留。
2. knowledge（create "回复里不要贴整段代码"）：epistemic 是 quote，但 refs 里没有一条是用户本人的话（@user）。
3. state：上一版第 3 项（"可以直接改 design.md"）这次没有写。每一项都要用 keep、update 或 close 写一次。
```

每一条问题用书记员自己写的东西指认是哪一条：有编号带编号（K12、第 3 项），有正文带正文的前 30 个字（摘要用标题）；两样都没有，或者同一个列表里两条指认出来一样时，才加"你交的第 X 个"（从 1 数）。不用从 0 数的位置号，因为它和"第 3 项"这类序号放在一起容易看混。

这次整理一次都没用过 search 或 read、提交又通过了检查时（先不保存，不算提交次数；之后交 `{"confirm": true}` 保存这一份，整份重交则换成新的；书记员停在这里或者用完提交次数，也保存这一份）：

```
这次整理还没有查过以前的记录，提交先不保存。对照一下这一批里有没有下面几种情况：
- 用户的一次性要求（"先讨论""先别动手""这次别提交"）：以前在别的事情上也说过的，要写成推断类规则；
- 改主意、推翻以前的做法，或者重新提起以前放下的事：对应的知识可能已经归档，你看不到；
- 看不懂的指代（"之前那台""最早那版""上次说的那个"），或者你在摘要里写了"没有说明""不清楚指什么"：答案多半在以前的摘要里；
- 用户纠正某条记忆：先 read 那一条，看原来写的是什么。
有的话，先用 search 或 read 查，查完要改的，整份重新提交。都没有，或者查完不用改的，调用 submit 并只写 {"confirm": true}，会原样保存刚才那份，不用把同样的内容再交一遍。这一步不算提交次数。
```

没有等确认的提交时交了 `{"confirm": true}`：

```
没有等你确认的提交。请整份提交。
```

通过：

```
已保存：2 份摘要，知识新建 1 条、更新 1 条，现状已更新。这次整理完成，不用再回复。
```
